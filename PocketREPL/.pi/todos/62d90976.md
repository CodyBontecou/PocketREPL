## Completed

Created the local model backend abstraction layer in `PocketREPL/LLM/`:

### Files Created

1. **ModelBackend.swift** - Core abstraction
   - `ModelState` enum: unloaded, loading(progress), ready, error, generating
   - `ModelError` enum: modelNotFound, insufficientMemory, loadFailed, inferenceError, cancelled, contextOverflow, invalidConfiguration
   - `GenerationRequest` struct with TaskKind (.generate, .fix, .complete, .explain)
   - `GenerationResponse` struct with token counts and finish reason
   - `StreamedGeneration` AsyncSequence for streaming tokens
   - `ModelConfiguration` struct for model loading settings
   - `ModelInfo` struct for runtime model metadata
   - `ModelBackend` protocol (actor-based) with load/unload/generate/cancel
   - `ModelBackendManager` @MainActor class for unified model management

2. **MockModelBackend.swift** - Test implementation
   - Simulates loading progress and generation delay
   - Provides template responses for different task types
   - Useful for UI development without real model

3. **PromptTemplates.swift** - Prompt formatting
   - `codeGeneration()` - New code from instruction
   - `codeFix()` - Fix broken code with error context
   - `codeCompletion()` - Complete partial code
   - `codeRewrite()` - Modify existing code
   - `agentWorkflow()` - Full agent prompt with tools
   - `parseToolCall()` - Extract tool calls from model output
   - `extractCode()` - Extract code from markdown blocks
   - `PromptBuilder` fluent API

### Key Design Decisions

- `ModelBackend` is an actor protocol for thread-safe inference
- `estimateTokens()` is `nonisolated` since it's a pure function
- `ModelBackendManager` is @MainActor for UI binding
- Streaming via AsyncThrowingStream for incremental token delivery
- Separate request types for different code tasks
- Token budgeting built into request/response types
