## Goal
Add llama.cpp source to the project and configure Xcode to compile the C/C++ code alongside Swift.

## Steps
1. Add submodule:
   ```bash
   cd /Users/codybontecou/projects/PocketREPL
   git submodule add https://github.com/ggerganov/llama.cpp vendor/llama.cpp
   ```

2. Create bridging header at `PocketREPL/PocketREPL-Bridging-Header.h`:
   ```c
   #ifndef PocketREPL_Bridging_Header_h
   #define PocketREPL_Bridging_Header_h
   
   #include "llama.h"
   #include "ggml.h"
   
   #endif
   ```

3. Configure Xcode project:
   - Build Settings → Swift Compiler - General → Objective-C Bridging Header: `$(SRCROOT)/PocketREPL/PocketREPL-Bridging-Header.h`
   - Build Settings → Apple Clang - Language - C++ → C++ Language Dialect: `GNU++17` or `C++17`
   - Build Settings → Search Paths → Header Search Paths: `$(SRCROOT)/../vendor/llama.cpp/include`
   - Build Settings → Search Paths → Library Search Paths: (if using prebuilt libs)

4. Add llama.cpp source files to Xcode project:
   - Add `vendor/llama.cpp/src/llama.cpp`
   - Add `vendor/llama.cpp/ggml/src/*.c` (core ggml files)
   - Add Metal shaders if targeting GPU: `vendor/llama.cpp/ggml/src/ggml-metal.m`

5. Add required frameworks:
   - Accelerate.framework
   - Metal.framework (for GPU)
   - MetalKit.framework (for GPU)

## Acceptance Criteria
- Project builds with llama.cpp included
- `#import "llama.h"` works in Swift via bridging header
- No linker errors

## Notes
- Consider using llama.cpp's CMake to build a static library instead of adding source files directly
- Alternative: Use Swift Package Manager with llama.cpp SPM fork
