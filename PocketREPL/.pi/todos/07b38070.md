## Goal
Establish the app structure for the offline JavaScript agent so future implementation work lands in stable modules instead of accumulating in `ContentView.swift`.

## Scope
- Create top-level structure for `Agent/`, `Project/`, `Runtime/`, `Tools/`, and `UI/`
- Define core app models for sessions, messages, tool traces, and execution results
- Replace the starter app shell with a minimal app-level composition root
- Keep the design compatible with iOS offline execution and future local model integration

## Deliverables
- Initial Swift files and folders for each subsystem
- Shared types for agent messages, tool events, and project metadata
- Clear ownership boundaries between UI, orchestration, runtime, and storage

## Acceptance criteria
- The project no longer relies on a single demo `ContentView`
- Core types compile cleanly and are easy to extend
- App startup path clearly constructs the project store, runtime, and session objects

## Notes
This is the foundation epic; avoid embedding storage or JS runtime details directly in the UI layer.

## Priority
- Priority: P0
- Order: 1 of 7
- Dependencies: none
- Rationale: establishes the module boundaries and shared types every other epic will build on.
