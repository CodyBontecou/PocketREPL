## Goal
Prevent tools from reading or writing outside the active project root.

## Scope
- Normalize relative paths consistently
- Reject `..`, absolute paths, and invalid components as needed
- Add helper APIs for resolving project-relative URLs safely

## Acceptance criteria
- Unsafe paths are rejected deterministically
- Valid project-relative paths resolve cleanly
- Tools can rely on one shared path-validation flow

Completed on 2026-03-10.

Added centralized relative-path normalization and traversal protection in `ProjectStore`.

Rejected cases include:
- absolute paths
- `..` traversal
- invalid/control-character components
- access to reserved `.pocketrepl` metadata paths

All path resolution now goes through `ProjectStore.resolve(relativePath:)`.
